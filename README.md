# 国际会议同声传译和发言队列控制

源提示词摘要：主持人维护代表发言队列、剩余时间、议题和临时插话；翻译团队维护多语种频道、术语和译员交接；字幕人员修正实时文本。队列调整保留版本，发言者切换后旧译文不会误绑定，并提供低延迟大屏模式和多会议厅隔离。

## 技术栈

Qwik City、TypeScript、Qwik UI、Qwik stores、TanStack Query、Modular Forms、Zod、qwik-speak。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62029`

## 可用流程

- 多会议厅独立维护代表、议题和发言队列，切换厅时数据互不影响。
- 发言人从排队、发言中、完成到跳过，支持临时插话和剩余时间调整。
- 多语种频道维护译员、术语和交接；交接后新增字幕归属新译员。
- 实时字幕支持版本化修正，低延迟模式只保留关键状态并停用非必要动态。
- 数据保存在浏览器 localStorage，刷新后继续保留。

## 断网可恢复指挥流（两台操作台）

每台操作台的每个操作（入队、状态变更、计时、交接启动/完成、字幕修订）都先记为一条**待同步操作**，带全局操作编号、所属会议厅、时间戳和对应的依据版本：

- **发言按厅内序号对应**：`speechSeq` + `statusVersion`。发言状态每次更新版本号 +1；对端操作基于旧版本时判定**失效**（时间线说明原因），不会把已完成发言改回排队。
- **交接按批次对应**：每次「开始交接」生成批次号（关联频道交接版本），「完成交接」必须批次与版本都对得上才生效；批次已关闭的迟到操作失效。字幕提交时快照译员与批次，旧译员字幕不会挂到新发言。
- **字幕按修订号对应**：`speechSeq + 语言 + baseRevision/revision`。对端基于旧修订号且内容不同 → 两版**分叉保留**，不互相覆盖；找不到对应发言的字幕进「挂空隔离」，只能人工挂接或丢弃，绝不猜挂到新发言。
- **冲突两边保留并列差异**：同基版本的状态分叉、字幕分叉、同批次双译员，都进入冲突清单，展示双方取值与字幕字符级差异，人工裁定后才收口。
- **按厅合并**：切换会议厅或恢复网络时只处理当前厅，其它厅的待同步操作原样保留；切台（1号/2号操作台视角）时未同步队列随操作归属走。
- **可恢复**：状态升级到 `schemaVersion: 2`（localStorage 键 `conference-interpretation-v2`）；旧 v1 存档首次打开自动迁移（补序号、状态版本、交接版本），未同步操作随存档持久化，重开浏览器仍在。

页面顶部可切换操作台视角、模拟断网/恢复，并可用「模拟对端断网期间操作」按钮构造旧版失效与分叉场景。
